### Como aplicar migration neste projeto
O `db push` arrasta tudo que está pendente. Com as 3 pendentes acima, é preciso movê-las para fora antes:

```bash
MIG="$PWD/supabase/migrations"; HOLD=$(mktemp -d)
restore() { mv "$HOLD"/*.sql "$MIG"/; }
trap restore EXIT
mv "$MIG"/20260817190000_*.sql "$MIG"/20260818024500_*.sql "$MIG"/20260818032000_*.sql "$HOLD"/
echo y | supabase db push --linked
```

⚠️ O `trap` precisa de caminho absoluto. Na primeira vez eu usei relativo e os arquivos voltaram para a raiz do repositório.

## 4. O padrão de defeito que domina este sistema

**Vocabulário divergente entre camadas, silencioso.** Quatro casos nesta sessão:

- `scope_type = 'loja'` contra enum `('store','department','individual','process')` → dois motores mortos por 3 meses
- `'MANUAL'` contra `'manual'` → contagens zeradas
- `SALES_WALKIN` contra `sales_door_flow` → todas as políticas sem efeito
- `applyTemplateToStore` onde o Base44 aplica ao cliente

**A causa raiz é uma só:** `src/lib/supabase.ts` cria o cliente como `createClient(...)` **sem `<Database>`**. Nenhuma consulta do projeto tem verificação de nome de tabela ou coluna. Sondei com uma tabela inexistente: zero erros de tipo.

**Medi o custo de ligar: 119 erros em 57 arquivos.** Não liguei, por dois motivos: é grande demais para carona, e `database.generated.ts` está desatualizado.

**Este é o item de maior alavancagem do backlog.** Ordem correta:
1. Destravar `npm run gen:db-types` — hoje falha com `Your account does not have the necessary privileges`. É permissão na conta Supabase, precisa de você.
2. Regenerar os tipos.
3. Ligar `createClient<Database>` e resolver os 119.

Feito isso, a classe de erro que consumiu metade desta sessão deixa de ser possível.
