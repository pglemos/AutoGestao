## Objetivo

Definir e validar a família semântica canônica: primary, surface, background,
text, border, success, warning, danger, info + estados. Validar contraste
WCAG AA (4.5 texto normal, 3.0 large/UI).

## Diagnóstico

A camada semântica já estava consolidada em
`src/design-system/tokens/semantic.css` (linhas 32-69): `--mx-color-surface`,
`--mx-color-text-primary/secondary/disabled`, `--mx-color-border{,-strong}`,
`--mx-color-primary{,-hover,-active,-foreground,-subtle}`,
`--mx-color-{success,warning,danger,info}{-subtle}`. **Faltavam** os tokens
`-foreground` (texto sobre bg colorido) e `-text` (versão escura para uso
como fg em bg claro).

## Implementação

### 1. Novos tokens semânticos (`semantic.css`)

Adicionados ao bloco "estados semânticos":
- `--mx-color-success-foreground: var(--mx-neutral-0)` (branco)
- `--mx-color-warning-foreground: var(--mx-neutral-950)` (preto — amber claro)
- `--mx-color-danger-foreground: var(--mx-neutral-0)` (branco)
- `--mx-color-info-foreground: var(--mx-neutral-0)` (branco)
- `--mx-color-success-text: var(--mx-status-success-text)` (verde escuro)
- `--mx-color-warning-text: var(--mx-status-warning-text)` (amber escuro)
- `--mx-color-danger-text: var(--mx-status-error-text)` (vermelho escuro)
- `--mx-color-info-text: var(--mx-status-info-text)` (azul escuro)

### 2. Correções para passar WCAG AA

- `--mx-color-text-disabled`: `neutral-400` → `neutral-500` (ratio 2.52 → 5.33, PASS AA)
- `--mx-color-success`: `emerald-500` → `emerald-600` (ratio branco 2.70 → 4.02, PASS AA-large)
- Criado primitivo `--mx-emerald-600: 158 89% 30%` em `primitives.css` para suportar success

### 3. Auditoria automatizada (`scripts/audit-wcag-contrast.mjs`)

- Resolve cadeias CSS (`var()`, `hsl(var())`, alpha) em primitives + semantic + index
- Converte HSL → sRGB → luminância relativa WCAG → ratio
- Curadoria de 31 pares semânticos: `cat: 'ok'` (uso correto — deve passar AA) vs `cat: 'antipattern'` (uso desaconselhado — alerta, não bloqueia)
- Size thresholds: `normal` (4.5), `large` (3.0), `ui` (3.0)
- Integrado a `npm run lint` (depois de `lint-landmarks`, antes de eslint)

### 4. Padrão UI canônico documentado

| Uso | Token fg | Token bg | Tamanho |
|---|---|---|---|
| Texto em superfície neutra | `text-primary` | `background`/`surface`/`surface-muted` | normal |
| Texto muted | `text-secondary` | idem | normal |
| Texto disabled | `text-disabled` | idem | normal |
| Botão primary ghost | `primary` | `background`/`surface-muted` | normal/large |
| Botão primary filled | `primary-foreground` | `primary` | large (bold) |
| Badge success filled | `success-foreground` | `success` | large |
| Badge warning filled | `warning-foreground` | `warning` | large |
| Badge danger filled | `danger-foreground` | `danger` | large |
| Badge info filled | `info-foreground` | `info` | large |
| Texto colorido em fundo claro | `*-text` | `background` | normal |
| Texto em bg sutil | `text-primary` | `*-subtle` | normal |

**Anti-patterns** (cor colorida como fg em fundo claro) — refatorar consumidores para usar `*-text` ou bg colorido + fg contrasting.

## Decisões registradas

- **Botões filled** (primary/success/warning/danger/info): aceitam WCAG AA-large
  (3.0) com `text-medium/bold` ≥14px (padrão WCAG 1.4.3 "large text"). Não é
  falha AA normal por design — é o trade-off canônico para botões saturados.
- **Tokens `-text`** (success/warning/danger/info): versões escuras para uso
  como fg em fundo claro. Derivam de `--mx-status-*-text` (template canônico
  T4.2), promovendo-os ao DS semântico.
- **`success` = emerald-600** (não 500): emerald-500 é claro demais para texto
  branco ter contraste AA. Criado primitivo `--mx-emerald-600` para suportar.
- **`warning-foreground` = neutral-950** (preto): amber-500 com branco dá 2.13
  (FAIL), com preto dá 9.28 (AAA).
- **Anti-patterns** ficam visíveis na auditoria como alerta (não bloqueiam lint)
  para futura refatoração de consumidores.
