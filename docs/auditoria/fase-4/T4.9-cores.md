# T4.9 — Consolidar Cores em Aliases Canônicos (DONE_WITH_EVIDENCE)

- SHA inicial: `1f4bea6b` (HEAD T4.8)
- Data: 2026-08-08
- Status: DONE_WITH_EVIDENCE
- Requisito: T4.8 Gap C — migração do padrão inline `-[hsl(var(--mx-color-*))]`
  para aliases canônicos `--color-*` do @theme (sprint futuro declarado em T4.8)

## Objetivo

Eliminar as 164 ocorrências de classes utilitárias com valor inline
`bg-|text-|border-|ring-[hsl(var(--mx-color-<token>))]` em 26 arquivos,
substituindo pelos aliases canônicos `--color-*` que o @theme já gera como
classes Tailwind diretas. Adicionar guard permanente `lint-colors` para
impedir regressão.

## Diagnóstico

- O audit advisory `scripts/audit-color-arbitrary.mjs` (criado na T4.8)
  inventariava 147 ocorrências `bg/text/border` + 16 `ring` + 1 `border` =
  **164 totais** em 26 arquivos.
- Padrão token-derivado (não violava `lint-tokens-ast`), porém verboso,
  inconsistente e não rastreável — misturava o acesso ao token com a utility.
- **Risco identificado**: o alias shadcn `--color-primary` NÃO podia ser
  assumido como equivalente direto — `--primary` (teal `176 100% 33%`) difere
  de `--mx-color-primary` (green `152 69% 31%`). Resolvido: a `semantic.css`
  re-mapeia `--primary: var(--mx-color-primary)` no `:root` (linha 109), então
  `bg-primary` = `hsl(var(--mx-color-primary))` por **paridade de valor**.
