## Correção implementada

`resolveChangedFiles(prev, cur)` com 4 camadas (ordem de tentativa):

1. **Diff local puro** — `git diff --no-renames --name-only --diff-filter=ACDMRTUXB prev..cur` se ambos existem.
2. **Fetch do objeto** — `git fetch --depth=1 origin <sha>` (15s timeout). Documentado: GitHub rejeita fetch por SHA; camada é tentativa e retorna `false` no catch.
3. **Unshallow da branch** — `git fetch --depth=3 origin main` (20s timeout). Aprofunda o clone raso (depth=1) o suficiente para conter o `prev` de deploys consecutivos. Segue `hasCommitLocally(prev)`.
4. **Fallback via API** — `GET https://api.github.com/repos/{owner}/{slug}/compare/{prev}...{cur}` (6s timeout via AbortController). Slug montado com `VERCEL_GIT_REPO_OWNER` + `VERCEL_GIT_REPO_SLUG` (nunca slug sem owner).

**Garantia estrutural:** qualquer caminho de falha (exceção, timeout, 404, objeto ausente) devolve `null` ou `undefined`, e `main()` responde `return 1` (build obrigatório). Nenhum caminho permite suprimir deploy por erro de inspeção.

**Detalhe de segurança:** `diffFilesViaApi` consome `response.json()` apenas se `response.ok`; loga o status HTTP em falha.
